# xgboost-metal

GPU-accelerated gradient boosting for Apple silicon, with the XGBoost Python API.
The native C++20 and Metal backend runs model training, prediction, evaluation
metrics, and feature contributions on the Apple GPU.

The package provides `DMatrix`, `QuantileDMatrix`, `train`, `cv`, and scikit-learn
estimators through the `xgboost` import. The distribution name is `xgboost-metal`.

## Origin

The initial prototype of xgboost-metal was generated by INT21's swarm.

## Features

- Histogram tree training for regression, classification, ranking, and survival analysis.
- Numeric and categorical features, native GPU sparse (`CSR`/`CSC`/`COO`) matrices, missing values, row weights, and sampling.
- Multioutput regression, quantile regression, tree dropout, and linear boosting.
- Early stopping, callbacks, continued training, and feature contributions.
- Zero-copy Apple unified-memory (`MetalArray`, PEP 3118, Arrow, DLPack) ingestion with zero required Python dependencies.
- JSON and UBJSON model exchange with XGBoost.

See [compatibility](docs/compatibility.md) for supported workflows and limitations.

## Requirements

| Component | Requirement |
| --- | --- |
| Hardware | Apple silicon Mac |
| Operating system | macOS 14 or later |
| Python | 3.10 or later |
| Source build | Xcode with the Metal compiler; CMake 3.24 or later |
| Python runtime | Zero required dependencies (optional NumPy, pandas, PyArrow, SciPy, scikit-learn) |

Metal is the execution backend. CPU and CUDA execution are not supported.

## Installation

Use a separate virtual environment because this distribution and upstream
XGBoost provide the same `xgboost` package.

```sh
git clone https://github.com/tabulai/xgboost-metal.git
cd xgboost-metal
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install ".[sklearn]"
```

The `sklearn` extra installs the dependencies for the example below. Use
`python -m pip install .` for the core Python API. See the
[installation guide](docs/installation.md) for toolchain setup and wheel builds.

## Quick start

```python
import xgboost as xgb
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split

X, y = make_classification(
    n_samples=10_000, n_features=32, n_informative=16, random_state=42
)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42
)

model = xgb.XGBClassifier(
    device="metal",
    tree_method="hist",
    n_estimators=100,
    max_depth=6,
)
model.fit(X_train, y_train)
print(f"Accuracy: {model.score(X_test, y_test):.3f}")
model.save_model("model.ubj")
```

Metal is selected by default. The explicit `device="metal"` parameter makes the
execution target clear in shared application code.

## Benchmarks

The M4 results below were measured on an **Apple M4 Max** (16 CPU cores, 128 GB unified memory, Release build without Metal validation layers), comparing `xgboost-metal` on the Apple GPU against regular OpenMP-enabled `xgboost 3.4.1` using all 16 CPU cores. Separate M1 Ultra MNIST measurements follow the M4 MNIST table.

### MNIST 10-Class Classification (`60,000 × 784` Train → `10,000 × 784` Test)

| Configuration | Metric | `xgboost-metal` (GPU) | `xgboost 3.4.1` (16-Core CPU) | Speedup / Delta |
| --- | --- | ---: | ---: | --- |
| **Default `XGBClassifier`** (`float64` `X/255`, `100` rounds = `1,000` trees, `max_depth=6`) | Train (`fit`) | **`9.47 s`** | `37.75 s` | **3.98× faster** |
| | Inference (`predict`) | **`7.29 ms`** | `18.18 ms` | **2.50× faster** |
| | Inference (`predict_proba`) | **`7.16 ms`** | `18.72 ms` | **2.61× faster** |
| | Test Accuracy / Log-Loss | **`98.00%` / `0.0647`** | `97.84%` / `0.0685` | **`+0.16%`** (`98.96%` agreement) |
| **Native `DMatrix` + `xgb.train`** (`float32`, `100` rounds = `1,000` trees, `max_depth=6`) | `DMatrix` Train Ingest (`188 MB`) | **`12.40 ms`** | `49.91 ms` | **4.03× faster** |
| | Pure `xgb.train` | **`9.41 s`** | `31.71 s` | **3.37× faster** |
| | Pure `Booster.predict(dtest)` | **`2.16 ms`** | `14.18 ms` | **6.56× faster** |
| | Test Accuracy / Log-Loss | **`98.00%` / `0.0647`** | `97.84%` / `0.0685` | **`+0.16%`** |
| **Native Sparse `CSR`** (`19.1%` nonzero pixels, `100` rounds = `1,000` trees, `max_depth=6`) | Pure `xgb.train` (`CSR`) | **`6.13 s`** | `20.45 s` | **3.33× faster** |
| | Pure `Booster.predict(dtest_csr)` | **`6.02 ms`** | `40.22 ms` | **6.68× faster** |
| | Test Accuracy / Log-Loss | **`97.71%` / `0.0735`** | `97.60%` / `0.0752` | **`+0.11%`** |
| **Tuned `XGBClassifier`** (`300` rounds = `3,000` trees, `max_depth=5`, `subsample=0.66`, `colsample_bytree=0.53`) | Train (`fit`) | **`26.97 s`** | `76.04 s` | **2.82× faster** |
| | Inference (`predict_proba`) | **`7.50 ms`** | `34.21 ms` | **4.56× faster** |
| | Test Accuracy / Log-Loss | **`97.87%` / `0.0654`** | `97.75%` / `0.0705` | **`+0.12%`** (`99.44%` agreement) |

### MNIST on Mac Studio M1 Ultra

Measured on an **Apple M1 Ultra** Mac Studio (20 CPU cores, 128 GB unified memory, macOS 26.5.1) using the published `xgboost-metal 0.1.0` wheel and the OpenMP-enabled `xgboost 3.4.1` wheel with 20 CPU threads. Both use the same `XGBClassifier` settings: 100 rounds, `max_depth=6`, `learning_rate=0.3`, `tree_method="hist"`, and `random_state=42`. The `float64` input matches the type in the M4 default-classifier result; the `float32` row repeats the earlier M1 comparison.

| Input | Metric | `xgboost-metal` (GPU) | `xgboost 3.4.1` (20-thread CPU) | Speedup / Delta |
| --- | --- | ---: | ---: | --- |
| `float64` `X/255` | Train (`fit`) | **9.38 s** | 24.03 s | **2.56× faster** |
| | Inference (`predict`) | **6.70 ms** | 12.33 ms | **1.84× faster** |
| | Inference (`predict_proba`) | **6.33 ms** | 12.31 ms | **1.94× faster** |
| | Test accuracy / log-loss | **97.95% / 0.0642** | 97.84% / 0.0685 | **+0.11 percentage points** |
| `float32` `X/255` | Train (`fit`) | **9.33 s** | 24.26 s | **2.60× faster** |
| | Inference (`predict`) | **5.14 ms** | 12.18 ms | **2.37× faster** |
| | Inference (`predict_proba`) | **4.91 ms** | 11.93 ms | **2.43× faster** |
| | Test accuracy / log-loss | **97.95% / 0.0642** | 97.84% / 0.0685 | **+0.11 percentage points** |

The M1 runs used the MNIST `train.csv.gz` and `test.csv.gz` files (60,000 training and 10,000 test images). Each backend was run in a separate process, alternating CPU and GPU; training times are medians of three fits and inference times are medians of 30 warmed calls per backend over the full test set. CSV loading is excluded from timings. Predictions agreed on 98.78% of test images for both input types. Other processes were active on the machine, so timings may vary with system load. The [MNIST benchmark script](benchmarks/mnist_classification.py) records individual timings, predictions, package versions, and input hashes.

### Core Training, Inference, Evaluation & Ingestion (`xgboost-metal` vs 16-Core CPU)

| Workload | `xgboost-metal` (GPU) | `xgboost 3.4.1` (16-Core CPU) | Speedup vs CPU |
| --- | ---: | ---: | ---: |
| Dense `hist` train (`262,144 × 64`, `100` rounds, `max_depth=8`) | **`264.1 ms`** | `1,055.6 ms` | **4.00×** |
| Dense `hist` train / predict (`100,000 × 32`, `100` rounds, `max_depth=6`) | **`164.5 ms` / `1.72 ms`** | `340.9 ms` / `7.37 ms` | **2.07× / 4.28×** |
| `multi:softprob` 5-class train (`100,000 × 32`, `50` rounds, `max_depth=6`) | **`226.7 ms`** | `726.7 ms` | **3.21×** |
| `monotone_constraints` `hist` train (`100,000 × 32`, `100` rounds, `max_depth=6`) | **`132.0 ms`** | `256.4 ms` | **1.94×** |
| `colsample_bylevel/bynode=0.5` `hist` train (`100,000 × 32`, `100` rounds) | **`163.7 ms`** | `291.6 ms` | **1.78×** |
| `subsample=0.7` `hist` train (`100,000 × 32`, `100` rounds, `max_depth=6`) | **`235.7 ms`** | `354.4 ms` | **1.50×** |
| Sparse `CSR` `hist` train (`200,000 × 512`, `2%` nnz, `50` rounds, `max_depth=6`) | **`192.9 ms`** | `752.1 ms` | **3.90×** |
| Sparse `CSR` predict (`200,000 × 512`, `50` rounds) | **`2.78 ms`** | `20.58 ms` | **7.41×** |
| Dense TreeSHAP `pred_contribs=True` (`65,536 × 32`, `100` trees) | **`74.1 ms`** | `1,153.4 ms` | **15.56×** |
| Sparse `CSR` TreeSHAP `pred_contribs=True` (`16,384 × 512`, `50` trees) | **`20.1 ms`** | `120.2 ms` | **5.99×** |
| Weighted `auc` + `aucpr` evaluation (`1,000,000` rows, GPU radix sort) | **`3.92 ms`** | `81.74 ms` | **20.86×** |
| 5-Fold `xgb.cv` (`100,000 × 32`, `40` rounds, `binary:logistic`, `logloss` + `auc`) | **`1.27 s`** | `1.95 s` | **1.53×** |
| `gblinear` `coord_descent` (`100,000 × 32`, `100` rounds, `cyclic` / `thrifty`) | **`303.4 ms` / `162.4 ms`** | `928.9 ms` / `361.7 ms` | **3.06× / 2.23×** |
| `DMatrix` ingestion (`100,000 × 32`: dense `f32` / Fortran / `f64` / `pyarrow.Table`) | **`1.07` / `0.92` / `1.06` / `2.19 ms`** | `3.35` / `3.40` / `3.51` / `4.70 ms` | **3.13× / 3.72× / 3.31× / 2.15×** |
| Page-aligned zero-copy `DMatrix` ingestion (`1,000,000 × 32`, `128 MB`) | **`7.66 ms`** | `24.94 ms` | **3.25×** |

Compared with the previous `xgboost-metal` baseline (`6cdb29d`), GPU radix-sort `auc`+`aucpr` is **34×–158× faster**, sparse `CSR` `DMatrix` ingestion is **30.7× faster** with **1.84× faster** training and **2.83× faster** prediction, 5-fold `xgb.cv` is **5.34× faster**, and constrained/sampled/multiclass GPU tree training is **2.05×–2.94× faster**.
